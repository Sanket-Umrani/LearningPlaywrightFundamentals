# Communication

- Self-identifies as a coding beginner and asks for explanations "line by line" — wants code walked through statement-by-statement in beginner-friendly terms rather than high-level summaries. Confidence: 0.6
- Learns concepts partly for job interviews: wants explanations delivered so a beginner can understand them and, often, in a ready-to-say interview answer format (framing the what/why/how/trade-offs). Confidence: 0.55
- Sends terse, command-only prompts — just the shell/npm command with no explanation or surrounding request (e.g. a bare `node auto-push-agent.js`) and expects it executed immediately, without clarifying questions or a restated plan. Confidence: 0.55
- Proposes a fix built on a simplified mental model and expects the agent to quietly do something *different but correct*: asked to move usernames/passwords to `.gitignore` (which controls file tracking, not text inside tracked files), with `<ide-context>` showing `.gitignore` as the open file. Right response is a one-or-two-sentence correction of the premise followed by the workable equivalent actually implemented — not literal compliance, not a lecture. Confidence: 0.6
- Proactively surfaces risks the automation itself creates (e.g. a doc generator inlining real credentials into a git-tracked README) and offers a concrete fix with `file:line` pointers plus concrete options (mask to first character + length, or keep only the line number) — raise the problem, don't silently fix it. Confidence: 0.6
- Wants compact post-command reports: what ran, the resulting diff stat, then the one thing to flag — not a long narration of the steps already taken. Confidence: 0.5
- For multi-file refactors, wants a bullet-per-file summary of what changed, a line stating how it was verified (the actual command and its signal, e.g. "45 tests compile, `injected env (10) from .env`"), and any residual matches accounted for rather than omitted. Confidence: 0.55
- Halts before irreversible or publishing actions (pushing to a public remote, rewriting tracked files) and hands control back with a short "I'm going to stop here rather than run it" plus numbered options — recommended option first, each one a concrete course of action, ending with a direct question. Confidence: 0.7
- Owns mistakes caused by the agent's own earlier step, not just its own misreads: when a generated change it ran introduced the leak it was now flagging, it said so explicitly ("that's on me for not stopping to check before regenerating") instead of presenting the problem as purely the user's. Confidence: 0.6
- Leads a follow-up report with the correction to the user's premise before any summary of what was done ("One correction first: `.gitignore` can't do what you asked…"), so the misunderstanding never silently becomes the record. Confidence: 0.6
- Reports self-corrections plainly when an intermediate check was wrong (e.g. "my earlier git check was malformed — `;` isn't a separator in cmd") rather than quietly correcting course, and gives the reason for the original conclusion being wrong. Confidence: 0.5
- Values the final report naming concrete content rather than just "done": lists which files/bytes changed, which concepts were covered, and surfaces any substantive finding the run produced (e.g. a code comment that contradicts what the code does) as something to fix in the user's own source. Confidence: 0.5
- Writes dense, run-on single-paragraph requests that bundle several requirements and enumerate alternatives inline ("1st way is X, 2nd way is Y"); expects the agent to parse all of it and implement every part rather than asking which one was meant. Confidence: 0.6
- Wants to fix problems themselves while learning: asks the agent to run code, list the errors, and "give a hint to resolve" them but explicitly "do not resolve it" — diagnose and suggest, don't apply fixes. Confidence: 0.7
